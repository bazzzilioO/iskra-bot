# Деплой и тестовое окружение

## Ветки

- **main** — прод. Сюда мержим только проверенный код.
- **staging** — тестовая ветка. Сначала деплоим сюда и гоняем тестового бота.

## Тестовый бот (рекомендуется)

Чтобы не лить изменения сразу в прод:

1. **Создать второго бота в @BotFather**
   - New Bot → имя, например `ИСКРА Test` или `ИСКРА Staging`.
   - Сохранить выданный **BOT_TOKEN** (отдельный от прод-бота).

2. **В Railway (или другом хостинге)**
   - Сделать **второй сервис** (дубликат текущего или новый проект).
   - В настройках репозитория указать ветку: **staging** (вместо `main`).
   - В переменных окружения задать:
     - `BOT_TOKEN` — токен **тестового** бота из шага 1.
     - Остальное можно скопировать с прода (или отдельная БД для теста, если нужна изоляция).

3. **Workflow**
   - Разработка и коммиты в `staging` (или в фичу-ветку → merge в `staging`).
   - Деплой тестового сервиса идёт с ветки `staging`.
   - Проверяешь в тестовом боте.
   - Если всё ок — merge `staging` → `main`; прод-сервис деплоит с `main`.

## Быстрый старт staging

```bash
# Переключиться на тестовую ветку и пушить
git checkout staging
git merge main   # подтянуть последний прод при необходимости
git push

# После проверки — выкатить в прод
git checkout main
git merge staging
git push
```
